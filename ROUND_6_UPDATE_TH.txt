STAR UP! ROUND 6 – บันทึกการอัปเดต
====================================

ไฟล์นี้พัฒนาต่อยอดจาก STAR_UP_UPDATE_ROUND_5_REV1.zip

สิ่งที่ปรับในชุดนี้
1) หน้า Dashboard ภาพรวม เพิ่มส่วน “ภาพรวมกิจกรรมทั้งห้อง” แสดงกิจกรรมแต่ละรายการ พร้อมจำนวนอนุมัติแล้ว / รอตรวจ / ยังไม่ส่ง / ต้องแก้ไข และแถบความคืบหน้า
2) เพิ่มหน้าต่างดูรายชื่อนักเรียนของแต่ละกิจกรรม พร้อมสถานะล่าสุดรายคน
3) เพิ่มปุ่มอนุมัติทั้งหมดและปฏิเสธทั้งหมดในหลักฐานภารกิจ โดยแสดงหน้าต่างยืนยันและจำนวนรายการ
4) เพิ่มปุ่มอนุมัติทั้งหมดและปฏิเสธทั้งหมดในคำขอแลกรางวัล โดยใช้ RPC เดิม teacher_handle_redemption ทีละคำขอ เพื่อคงกลไกหักดาว/ตัดสต็อกเดิม
5) เปลี่ยนชื่อปุ่มเป็น “ลบรายชื่อนักเรียนทั้งห้อง” และใช้หน้าต่างยืนยัน/ยกเลิกโดยไม่ต้องพิมพ์คำว่า “ลบ”
6) ปรับการปิด Modal: ไม่ปิดเมื่อคลิกพื้นหลัง ลดโอกาสปิดโดยไม่ตั้งใจระหว่างลากเลือกข้อความ
7) ปรับหน้าต่างเริ่มต้นให้ภาพโลโก้อยู่ในวงกลมแบบ contain เพื่อลดการตัดขอบ
8) ปรับป๊อปอัปภารกิจด่วนให้แสดงภารกิจที่ยัง active ทุกครั้งเมื่อเข้าโปรไฟล์ใหม่ ไม่จำสถานะปิดข้ามการล็อกอิน และยังมีปุ่มปิดด้วยตนเอง
9) ปรับเลขเวอร์ชัน Service Worker เพื่อให้เบราว์เซอร์ดึงไฟล์ใหม่

ฐานข้อมูล / SQL
- ชุดนี้ไม่เพิ่มตารางหรือคอลัมน์ใหม่ จึงไม่มี migration_round6.sql ที่ต้องรัน
- ใช้ตารางและ RPC เดิมจาก Round 5 / migration เดิม
- โปรดสำรองฐานข้อมูลก่อนเผยแพร่ทุกครั้ง

ข้อจำกัดและสิ่งที่ต้องทดสอบในระบบจริง
- Dashboard นับสถานะจาก mission_submissions ที่โหลดในหน้าแอป (query ปัจจุบันของโปรเจกต์จำกัดผลลัพธ์ไว้ 150 รายการ) หากห้องมีประวัติการส่งเกิน 150 รายการ ควรเพิ่ม pagination ก่อนใช้ตัวเลขเป็นรายงานทางการ
- สถานะของนักเรียนต่อกิจกรรมใช้รายการส่งล่าสุดที่อยู่ในชุดข้อมูลที่โหลด
- ปุ่มอนุมัติ/ปฏิเสธแบบกลุ่มเรียก RPC เดิมแยกทีละรายการ หากรายการใดผิดพลาด ระบบจะแสดงจำนวนที่ทำสำเร็จก่อนเกิดข้อผิดพลาด ต้องตรวจรายการคงเหลือแล้วดำเนินการต่อ
- ต้องทดสอบ RPC teacher_handle_redemption บน Supabase จริงก่อนใช้ปุ่มอนุมัติคำขอแลกทั้งหมด เพราะชุด SQL ที่แนบใน ZIP ต้นฉบับไม่มีนิยาม RPC นี้ให้ตรวจสอบ
- การลบรายชื่อนักเรียนทั้งห้องใช้ RPC teacher_delete_students เดิม หรือ fallback เดิม หาก RPC ไม่มีอยู่จะพยายามลบแถว students ตาม RLS; โปรดทดสอบบนห้องสำรองก่อน
- ไม่สามารถยืนยันการแสดงผลจริงบนอุปกรณ์ Android/iOS ได้จากการตรวจโค้ดเพียงอย่างเดียว

การติดตั้ง
1) ดาวน์โหลด ZIP และสำรอง Repository GitHub เดิมก่อน
2) แตกไฟล์ ZIP ในเครื่อง
3) เปิดโฟลเดอร์ STAR_UP_MISSIONS ด้านใน
4) อัปโหลดเนื้อหาภายในโฟลเดอร์นี้ทับไฟล์เดิมใน Repository starup โดยคงตำแหน่ง index.html, teacher/, student/ และไฟล์ประกอบให้เหมือนเดิม
5) Commit changes และรอ GitHub Pages เผยแพร่
6) เปิดหน้าแอปครูบน Mac กด Command + Shift + R; บน Android ปิด/เปิดแอปใหม่หรือรีเฟรชหน้าเว็บ
7) ทดสอบในห้องสำรองก่อน: Dashboard, ดูสถานะรายชื่อ, ส่งภารกิจทดสอบ, อนุมัติ/ปฏิเสธแบบกลุ่ม, คำขอแลก, ลบรายชื่อนักเรียนทดสอบ

คำเตือน
อย่าอัปโหลดเฉพาะไฟล์ teacher/index.html หรือ student/index.html เพียงไฟล์เดียว เพราะ Service Worker, manifest และ assets ต้องตรงเวอร์ชันกัน
